# AI и поиск

Стек по умолчанию: **Gemini** анализирует фото, **serper.dev** ищет (Google Lens по фото и Google по описанию).
Anthropic и Jina не нужны. Их можно подключить как альтернативу, они описаны ниже.

| Задача | Что делает | Провайдер (`.env`) |
|---|---|---|
| Анализ фото | проверяет, что на фото товар; определяет категорию, цвета, материал, силуэт, стиль, бренд (только при явных признаках); строит поисковые фразы на RU, EN и ZH | `VISION_PROVIDER=gemini` (по умолчанию), `anthropic` или `openai_compatible` |
| Поиск по фото | Google Lens через serper.dev: страницы с такой же или похожей вещью | `LENS_PROVIDER=serper` (по умолчанию) или `google_vision` |
| Поиск по описанию | Google через serper.dev по доменам площадок, по фразам из анализа фото | `TEXT_SEARCH_PROVIDER=serper` (по умолчанию) или `claude` |
| Процент сходства (опционально) | эмбеддинги изображений, cosine, калиброванный % | `EMBEDDING_PROVIDER=none` (по умолчанию), `jina` или `voyage` |

**Без эмбеддингов процента сходства нет**, и это честно: карточки сортируются по порядку выдачи Lens (сначала
полные совпадения фото), а процент не рисуется. Чтобы он появился, подключите Jina или Voyage (раздел ниже).

Устойчивость: если Gemini недоступен, поиск всё равно идёт через Lens по фото. Ошибкой `ai_unavailable` (с возвратом
квоты) поиск завершается только когда не работает ни анализ, ни эмбеддинги, ни Lens.

## Gemini (анализ фото)

```
VISION_PROVIDER=gemini
GEMINI_API_KEY=...          # aistudio.google.com/apikey
GEMINI_MODEL=gemini-2.5-flash
```

- Ответ строго по JSON-схеме (`responseJsonSchema`). Если модель не принимает схему, SIFT передаёт схему в промпте
  и проверяет ответ валидатором.
- Имена моделей Gemini меняются: сверьте актуальное в Google AI Studio и при необходимости поменяйте `GEMINI_MODEL`.
- Если Gemini заблокировал фото фильтром безопасности, это видно в логах worker, а поиск продолжается через Lens.

## serper.dev (Google Lens и Google)

```
LENS_PROVIDER=serper
TEXT_SEARCH_PROVIDER=serper
SERPER_API_KEY=...          # serper.dev → API Key
SERPER_COUNTRY=ru
SERPER_LANGUAGE=ru
```

- Один поиск пользователя тратит до 3 запросов serper.dev: Lens плюс до двух запросов в Google (русскоязычные
  площадки с русской фразой, международные с английской). Планируйте пакет кредитов serper.dev из этого расчёта (у Lens может быть своя цена в кредитах).
- serper.dev забирает фото по подписанной ссылке с вашего домена, поэтому `PUBLIC_BASE_URL` должен открываться из интернета.
- Подробности про площадки и юридический статус serper.dev в [MARKETPLACES.md](MARKETPLACES.md).

## Альтернатива: Claude (анализ фото и веб-поиск)

```
VISION_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
ANTHROPIC_MODEL=claude-opus-5-5
ANTHROPIC_EFFORT=low            # быстро и дёшево; для тарифов с «глубоким анализом» используется medium
ANTHROPIC_SERVER_FALLBACKS=true # при перегрузке модели запрос автоматически уходит на резервную
```

- Ответ строго по JSON-схеме (structured outputs), поэтому парсинг не ломается.
- Если на фото нет товара (пейзаж, еда, скриншот текста), модель возвращает
  `is_product=false` и причину, а пользователь видит понятное сообщение.
- Бренд указывается, только если он виден (логотип, бирка). Иначе пусто, без догадок.
- Ключ: [console.anthropic.com](https://console.anthropic.com) → API Keys. Поставьте лимит расходов в Billing.

Альтернатива: любой OpenAI-совместимый endpoint с vision (`OPENAI_COMPAT_BASE_URL`, `OPENAI_COMPAT_API_KEY`,
`OPENAI_COMPAT_MODEL`).

## Эмбеддинги

```
EMBEDDING_PROVIDER=jina
JINA_API_KEY=jina_...
JINA_MODEL=jina-clip-v2
EMBEDDING_DIM=1024
```

- Jina CLIP v2: изображения и тексты в одном пространстве, 1024 измерения. Ключ: [jina.ai](https://jina.ai).
- Voyage multimodal-3: `EMBEDDING_PROVIDER=voyage`, `VOYAGE_API_KEY`. Тоже 1024 измерения.
- Эмбеддинги товаров кэшируются в Postgres (pgvector, индекс HNSW): повторно встреченный товар не пересчитывается.
- **Размерность фиксируется при первой миграции.** Смена модели на другую размерность требует новой миграции
  и пересчёта эмбеддингов. Смена модели той же размерности требует только пересчёта: старые векторы помечены
  `model_id` и не смешиваются с новыми.

## Процент сходства: только реальный и откалиброванный

Процент показывается **только** когда эмбеддинги посчитаны для запроса и для кандидата. Иначе у карточки нет
процента, а результаты сортируются по релевантности площадки.

Процент получается линейным отображением cosine: `LOW` даёт 0 %, `HIGH` даёт 100 %. Значения по умолчанию
(0.55 / 0.93) являются стартовыми. **Перед запуском откалибруйте их на своих данных**:

1. Соберите CSV из 100 и более пар: `image_a,image_b,label`, где `label` один из `same` (тот же товар,
   другое фото или продавец), `similar` (приемлемая альтернатива) или `different` (другой товар той же
   категории). Подойдут URL или локальные пути.
2. Запустите:
   ```bash
   docker compose cp pairs.csv worker:/data/uploads/pairs.csv
   docker compose exec worker python -m app.cli.calibrate /data/uploads/pairs.csv
   ```
3. Скрипт покажет распределение cosine по классам и предложит `SIMILARITY_CALIBRATION_LOW` (90-й перцентиль
   `different`) и `SIMILARITY_CALIBRATION_HIGH` (медиана `same`). Впишите их в `.env` и выполните
   `docker compose up -d`.
4. Если классы перекрываются, скрипт так и скажет. Тогда модель не различает ваши данные, и проценты
   показывать нельзя: смените модель или отключите эмбеддинги.

Перекалибруйте при смене модели эмбеддингов.

## Дубликаты

Один и тот же товар от разных продавцов одной площадки (одинаковая картинка или cosine ≥ 0.985 при похожем
названии) сворачивается. Одинаковые товары на **разных** площадках не скрываются: сравнение цен между
площадками и есть ценность продукта.

## Режимы поиска

| Режим | Ранжирование |
|---|---|
| Точно | максимальный вес визуального сходства |
| Похожие | сходство плюс небольшой вклад релевантности площадки |
| Дешевле | бонус за цену ниже ориентира (медиана цен самых похожих вариантов), а не дешевле опускаются вниз |
| Стиль | более широкие запросы (`discover_queries`) по стилю, а не по конкретной вещи |

Товар без эмбеддинга никогда не обгоняет товар с реальным визуальным совпадением.

## Стоимость и контроль

- Один поиск = 1 вызов Claude (одно изображение до 1280 px плюс короткий ответ) и 1 батч эмбеддингов на запрос
  плюс до 150 кандидатов (меньше, если они уже в кэше).
- Админ-панель → «Интеграции» показывает число вызовов, ошибок и среднюю задержку AI.
- Ограничьте траты лимитами в консолях провайдеров. При исчерпании лимита поиски корректно завершаются
  с `ai_unavailable` и возвратом квоты.

## Фото в карточках

Карточка показывает фото, которое нашёл поиск: картинку из Google Lens для совпадений по фото и
картинку из Google Images (`SERPER_IMAGES=true`, тот же serper.dev) для результатов текстового поиска.
Воркер один раз скачивает каждое такое фото (SSRF-защита, лимит размера, 384px JPEG) и хранит у себя
в `storage/thumbs/`, Mini App получает подписанную ссылку на эту копию. Так фото не ломаются из-за
запрета хотлинка или протухших ссылок CDN. Если площадка не отдала картинку, берётся миниатюра Google,
а в карточке остаётся исходная ссылка как запасной вариант. Копии удаляются по `UPLOAD_RETENTION_DAYS`
для товаров, которых давно нет в выдаче и нет в избранном.
