# Архитектура SIFT

## Схема

```
 Telegram ──► bot (aiogram) ──────────────┐
    │                                     │ create_search / payments
    ▼                                     ▼
 Mini App (React) ─HTTPS─► nginx ─► api (FastAPI) ──► PostgreSQL 17 + pgvector
                             │         │    ▲              ▲
                             │         ▼    │              │
                             │       Redis (кэш, лимиты, брокер)
                             │         │                   │
                             │         ▼                   │
                             │      worker (Dramatiq) ─────┘──► Gemini · serper.dev (Lens, Google)
                             │         │
                             │         └──► eBay · AliExpress · Taobao API · фиды (pgvector)
                             └─ статика Mini App, TLS (certbot)
 scheduler ──► подписки, триал, напоминания, здоровье площадок, курсы ЦБ, ценовые алерты, очистка
 backup    ──► pg_dump ежедневно
```

## Репозиторий

```
backend/
  app/api/          FastAPI: роуты, зависимости (initData-аутентификация), сериализация
  app/bot/          aiogram: команды, поиск по фото, платежи
  app/ai/           анализ фото (Gemini / Claude / OpenAI-compatible), эмбеддинги (Jina / Voyage, опционально)
  app/marketplace/  контракт провайдера, адаптеры площадок, Lens и веб-поиск, реестр
  app/search/       пайплайн поиска и ранжирование
  app/services/     бизнес-логика: пользователи, подписки, платежи, триал, рефералы, изображения, FX
  app/workers/      брокер, акторы Dramatiq, планировщик
  app/cli/          импорт фидов, калибровка сходства
  app/db/           модели SQLAlchemy, сессии
  migrations/       Alembic
  tests/            unit + интеграционные (реальные Postgres и Redis)
frontend/           Mini App
infrastructure/     nginx, postgres, redis, certbot, backup
scripts/            установка, сертификат, бэкап, восстановление, деплой
.github/workflows/  CI и деплой
```

## Поток поиска

1. **Загрузка** (`POST /api/v1/searches` из Mini App или фото в бот). Проверка формата по сигнатуре
   (JPEG, PNG, WebP), размера (≤ 10 MB) и числа пикселей (≤ 40 MP, защита от decompression bomb). Затем
   перекодирование в JPEG с удалением EXIF (геометка не сохраняется), уменьшение до 1280 px и dHash.
2. **Дедупликация.** То же фото с теми же параметрами за 10 минут возвращает существующий поиск. Плюс заголовок
   `Idempotency-Key` от Mini App.
3. **Квота** резервируется под advisory-lock (тариф, затем бонусные поиски).
4. **Очередь.** PRO и ULTRA идут в `search_priority`, Free в `search` с лимитом 2 одновременных поисков.
5. **Анализ и эмбеддинг** выполняются параллельно. Стадии пишутся в `search_sessions.stage`, и Mini App
   показывает их в реальном времени.
6. **Площадки опрашиваются параллельно** с таймаутом на каждую. Статус и число найденного по каждой площадке
   пишутся сразу (JSONB-merge), поэтому пользователь видит прогресс.
7. **Приём кандидатов.** Upsert товаров, история цен, загрузка миниатюр (защита от SSRF: только http(s),
   публичные IP, лимит размера), эмбеддинги с кэшем по `model_id`.
8. **Ранжирование:** cosine, калиброванный процент, режим, свёртка дубликатов.
9. **Завершение.** Если результат отрицательный по нашей вине (AI или все площадки недоступны), квота
   возвращается. Зависшие больше 10 минут поиски закрывает планировщик и тоже возвращает квоту.

## Безопасность

| Угроза | Защита |
|---|---|
| Подделка пользователя | каждый запрос API: HMAC-проверка `initData` (ключ из `BOT_TOKEN`) и проверка срока `auth_date` |
| Доступ к чужим данным | все выборки фильтруются по `user_id`; избранное можно добавить только из своих поисков |
| Админ-доступ | только `ADMIN_TELEGRAM_IDS`, проверка на сервере; действия админов пишутся в `admin_logs` |
| Злоупотребление API | nginx: 20 запросов/с на API и 1/с на загрузку (с burst); приложение: 180/мин на пользователя |
| Вредоносные файлы | проверка сигнатуры, лимиты размера и пикселей, перекодирование, удаление метаданных |
| SSRF через URL картинок | только http(s), резолв и запрет приватных и loopback-адресов, лимит размера и таймаут |
| Медиа | загруженные фото отдаются только по подписанным ссылкам с истекающим сроком |
| Платежи | доступ выдаётся только после `successful_payment`; уникальный `telegram_payment_charge_id`; сверка суммы, валюты и владельца в `pre_checkout` |
| Webhook бота | секрет в заголовке `X-Telegram-Bot-Api-Secret-Token` |
| Секреты | только в `.env` (права 600), не в образах и не в репозитории |
| Сеть | наружу открыты только 80 и 443 (nginx); Postgres и Redis только во внутренней сети Docker |
| Заголовки | HSTS, CSP (скрипты только свои и telegram.org; frame-ancestors только Telegram), nosniff, Referrer-Policy |
| Контейнеры | backend работает под непривилегированным пользователем (uid 10001), init-процесс, лимиты памяти и CPU |

## Данные

- `users`: Telegram-профиль, реферальный код, бонусы, триал, настройки, блокировка.
- `plans`, `subscriptions`, `payment_intents`, `payments`: биллинг.
- `search_sessions`, `search_results`, `products`, `product_embeddings` (vector 1024, HNSW), `price_history`, `favorites`.
- `referrals`, `referral_rewards`, `marketplace_status`, `app_settings`, `admin_logs`.

## Масштабирование

Текущая конфигурация рассчитана на 4 vCPU и 8 GB. Порядок наращивания:
1. `worker --threads` и второй контейнер worker (поиск упирается в сеть, а не в CPU).
2. `api --workers` по числу ядер.
3. Вынести Postgres на отдельный сервер или управляемый сервис.
4. Хранилище фото перенести в S3-совместимое (интерфейс `Storage` уже выделен).
